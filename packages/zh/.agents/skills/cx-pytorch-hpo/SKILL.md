# cx PyTorch 统一调参

## 目的

建立模型无关、证据驱动的调参循环。不再区分轻量与全量调参，不抽取十分之一实体，不预排候选。模型目录只声明配方；公共模块拥有数据边界、训练、验证、监控、比较、分析和继续门禁。

## 不可变约束

1. 先读当前项目 AGENTS.md、实际配置、公共训练和调参入口、调用方、测试、冻结基线和历史产物。Git 历史中的旧实现只作恢复线索。
2. 已有模型无关调参模块时必须演进它，不在具体模型目录复制候选循环、配置改写、监控、排名或报告。模块已删除但 Git 历史存在时，先审计删除原因、旧依赖和现行接口，再以 TDD 恢复所需能力。
3. 从模型正式配置构造类型化配置对象，只在内存中执行不可变替换。实验参数不得改写产品默认配置；完整实际配置与每个权重一一冻结。
4. 股票调参固定使用适用注册制生效日起的全部合格实体和全部合格日线。创业板默认起点为 2020-08-24；项目有更精确的已审计事实时服从项目。禁止抽取十分之一股票、为了资源缩小股票覆盖，或把注册制以前历史称为调参全量数据。
5. 时间切分、标签、级别、排序分数和命中定义均来自项目权威入口。不得把标签擅自改成开盘跳空、真实收盘回归或其它目标；标签、切分或业务评价改变后进入新的业务可比组，损失改变后只进入新的损失可比组。
6. 训练集训练，验证集选择权重、阈值、候选和下一改动。严格测试只能审计冻结候选，其指标不得进入轨迹分析或下一候选选择；一旦参与选择，停止并声明测试集污染。
7. 每次只启动一个完整候选。禁止预排队、连续自动运行或预先固定五候选。候选结束后先分析；只有一个可证伪原因和一个唯一最小改动成立时才可继续。
8. 验证业务目标是候选选择的第一目标。验证损失用于反向传播、检查点和收敛诊断；业务指标持续下降时，不得仅因损失改善而晋级。类别权重等方案已被当前项目证据否定时，不得无新假设重复消耗预算。
9. 用户硬件、内存和时限是门禁。启动前以真实张量形状和最小试运行估算显存、系统内存、每轮时间和总时间；只能调整尚未冻结的容量、批次或精度，不能改变数据覆盖和用户固定维度。
10. 按项目规则冻结业务最优、最小验证损失和真实最终状态全部检查点。严格测试只使用项目规定的检查点。

## 公共模块协议

公共调参模块是以下生命周期的唯一实现：

- 接收一个候选及其内存配置，不接收候选队列。
- 校验注册制起点、全部合格实体、时间切分、数据版本和内容摘要。
- 调用独立训练与验证入口；模型薄封装只构造网络、损失和配方。
- 每轮记录训练/验证损失、首要业务指标、学习率、耗时、吞吐、图形处理器利用率、显存、系统内存和进程内存。
- 候选结束后冻结配置、规定检查点、历史、资源、验证预测、业务指标和分析。
- 校验前后候选只有一个 changed_dimension。业务指标只在相同标签、切分和业务评价的 business_comparison_group 内比较；验证损失只在相同损失定义的 loss_comparison_group 内比较。
- 在分析结论为 continue 前拒绝启动下一候选。

不要原样恢复以 QuickTune 命名、顺序执行全部试验或把业务指标置于损失之后的旧接口。可以复用其薄适配器、内存配置、验证隔离、资源审计和冻结产物设计。

## 极端不平衡目标

1. 先用现行源码、配置和正确数据边界复跑并冻结基线，未复现前不改算法。
2. 声明一个验证业务主指标，例如每日动态 TopN 最高两级精确率或固定 Top10 命中率；同时保存召回率、入选收益、尾部风险和逐日稳定性。
3. 九级分类保存逐类支持数、混淆、最高两级精确率与召回率、预测覆盖和校准；总体准确率不能替代最高两级目标。
4. 多分类、序数、可微排序、成对排序或 TopK 组合损失均可作为候选，但一次只改变损失。损失值进入新的损失可比组而不直接比较；标签、切分和业务评价不变时，业务指标仍在同一业务可比组比较。
5. 不使用严格测试挑选权重、阈值、TopN、损失、结构或超参数。

## 单候选循环

1. 建立范围清单，把字段、标签、窗口、模型容量、纵向与横截面摘要容量、损失、优化器、学习率、调度器、批次和精度标为用户固定、参与搜索或有证据排除。
2. 复跑基线并冻结业务主指标、验证损失、资源、三权重和数据摘要。
3. 从上一分析提出一个可证伪假设，只改变一个维度；无假设时停止。
4. 通过资源门禁后启动，逐轮写结构化产物，至少每五分钟汇报进度或停留点。
5. 候选结束后只读取训练和验证产物，运行 scripts/analyze_hpo_progress.py；工具未给出 continue 时不得训练下一候选。
6. 分析相对基线和上一候选的业务变化、连续退化、损失与业务冲突、有效改善、最佳轮次、资源、失败和可比性。
7. 业务主指标连续两个可比候选显著低于基线，或损失改善而业务显著退化时，停止完整候选链；先修正目标、做最小诊断或回到基线。
8. 只有业务目标实质改善且风险与资源未退化时，才提出下一个单变量实验。小于项目最小有意义差异的变化不作强结论。
9. 最终配方冻结后才运行严格测试和回测；验证与严格测试分开报告。

## 轨迹分析工具

运行：

    python scripts/analyze_hpo_progress.py path/to/ledger.json path/to/analysis

台账包含 data_scope、objective、baseline_trial、trials、strict_test_used_for_selection 和最多一个 proposed_next。每个完成候选记录名称、business_comparison_group、loss_comparison_group、业务主指标、最佳/最终验证损失、完成/计划轮次、最佳轮次、资源门禁和唯一 changed_dimension。

工具输出 analysis.json 与 analysis.md，强制注册制全部实体，拒绝严格测试参与选择，并识别连续业务退化、损失与业务冲突、不可比候选、多项改动、无有效改善和资源失败。它只分析证据，不启动训练。

## 完成证据

- 公共调参模块与调用方审计，以及旧实现取舍。
- 注册制起点、合格实体数、日期范围、三段边界、数据版本和内容摘要。
- 冻结基线、范围清单、每候选唯一改动和完整配置。
- 每轮业务、损失和资源轨迹；每候选三权重、验证预测与分析文件。
- 相对基线的业务变化、连续退化、目标冲突及停止或继续理由。
- 最终冻结配方的严格测试和回测，且证明它们未参与选择。
