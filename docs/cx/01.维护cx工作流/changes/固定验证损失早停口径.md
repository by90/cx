# 变更：固定验证损失早停口径

## 当前事实

- 全局规则和机器学习技能已经要求逐轮报告早停计数、验证损失与业务指标，但没有明确规定早停计数只能由验证损失驱动。
- `$cx-pytorch-hpo` 仍允许项目验证选择目标决定训练早停，可能把 TopN 等业务指标误接到早停回调。
- 业务指标需要继续用于观察、候选比较和业务最优权重冻结，但不能结束训练。

## 目标状态

1. 训练早停只监控 `validation_loss` 的严格改进，并按越小越好累计忍耐计数。
2. TopN、Top1、Top3、Top5、Top10 等业务指标只用于逐轮报告、候选比较和独立业务最优检查点，不参与早停计数或重置。
3. 每轮报告的早停 `x/y` 明确表示验证损失连续未达到最小改进量的轮数与忍耐上限。
4. 调参技能、时间序列技能、审查技能、全局规则及其中英文安装镜像保持同义。
