# 变更：强化调参资源容量门禁

## 目标

让 `$cx-pytorch-hpo` 在启动正式调参、领取新 trial、启动测试或分析器等辅助进程，以及训练运行期间，持续核对中央处理器、系统物理内存、系统提交内存和逐卡显存，避免超过本机容量导致训练、终端或 Codex App 崩溃。

## 当前事实

- 现行技能只要求启动前估算系统内存、显存和每轮时间，未规定辅助进程启动前重新准入。
- Windows 的物理可用内存不能代表提交内存余量；双卡训练与测试、分析器并行时可能仍因提交上限失败。
- 高资源工作默认逐个串行；只有容量预算证明安全时才允许双卡各运行一个 trial，同时进行的高资源工作绝不超过两个。
- 正式股票范围、标签和业务目标不得因资源不足而缩小；资源冲突应通过等待、串行或减少并发进程解决。

## 顺序工作清单

1. 修改原任务 `tasks/04.同步双语安装包.md`，登记可执行的容量门禁和验证要求。
2. 先修改中文 `$cx-pytorch-hpo` 源技能和安装包镜像。
3. 同步英文源技能和安装包镜像。
4. 验证双语镜像、资源门禁关键词、技能包和安装包。
5. 执行交付物质量审查和完成证据门禁；通过后删除本变更文件。

## 完成条件

- 技能明确区分物理可用内存与提交内存余量。
- 每次启动正式调参、领取新 trial 或辅助进程前都执行容量准入。
- 默认串行处理；双卡并行最多两个高资源工作，双卡训练期间不得再并行启动完整测试、分析器或其它高资源任务。
- 运行中持续记录中央处理器、内存、提交内存和逐卡显存，并在容量不足时不启动新工作。
- 不通过缩小注册制股票覆盖、吞掉异常或盲目重试规避容量问题。
- 中文先完成，英文语义等价，源技能与安装包镜像一致。
