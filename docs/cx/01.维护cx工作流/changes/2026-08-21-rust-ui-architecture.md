## 当前事实

`cx-rust-tdd` 仍允许在生产源码中放置 `#[cfg(test)]` 测试模块，未要求 `tests/` 与 `src/` 一对一镜像。现有技能集合也没有独立的 UI 分层技能，无法把页面、组件、视图模型、服务和数据访问的文件与依赖边界作为明确门禁。

## 目标状态

Rust 测试只存在于与 `src/` 同级的 `tests/`，测试目录尽可能镜像源码目录，一个被测源码文件最多对应一个同名 `_test.rs` 文件。UI 开发使用独立技能贯彻 View、ViewModel、Service、Data 单向分层，每个页面、组件和视图模型分别位于独立文件；工作流、设计和审查技能能够正确路由并验证这些规则。中英文技能源、安装包镜像、清单和本机中文安装结果保持一致。

## 主要变化

1. 改写 `cx-rust-tdd` 的 Rust 测试布局，禁止生产源码中的测试代码。
2. 新增 `cx-ui`，明确页面、组件、视图模型、服务和数据访问边界。
3. 更新 `cx-workflow`、`cx-design`、`cx-review` 和原任务，使技能路由与交付门禁覆盖新规则。
4. 同步中英文源技能、安装包镜像与清单，验证后推送 `main` 并本地重装中文 cx。
