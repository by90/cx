# 统一注册制调参与过程分析

## 背景

现有 `$cx-pytorch-quick-hpo` 把数据固定为十分之一完整实体，并预先形成五个候选；`$cx-pytorch-full-hpo` 再在全部样本上逐一运行候选。该二段边界会让小样本结论支配昂贵实验，也不能直接解释业务指标为何在连续候选中持续下降。

目标项目 `iget` 已经有过模型无关的 `src/run/tune.py` 公共调参生命周期。该实现于精简提交 `786ea49` 删除；本次不能另造模型专属调参器，应复用其“模型薄适配器、内存配置、统一训练入口、冻结产物、验证集选择”的公共协议，并替换旧的轻量/全量推进语义。

## 当前变更

1. 删除快速调参与全量调参的双技能边界，建立唯一的 `$cx-pytorch-hpo` 中英文技能。
2. 股票任务的调参数据固定为注册制生效日起的全部合格股票和全部合格日线，不再抽取十分之一股票，也不再切换到注册制以前的所谓全量历史。验证集只承担候选选择；严格测试集不得进入调参。
3. 每次只运行一个候选。候选完成后先对验证业务指标、验证损失、收敛、资源、失败和相对冻结基线的变化做结构化分析；只有形成一个可证伪原因及一个唯一最小改动，才允许启动下一候选。
4. 新增通用调参轨迹分析工具和测试。工具读取公共 JSON 产物，输出机器可读分析及 Markdown 摘要，至少识别业务指标连续退化、损失改善而业务退化的目标冲突、无有效改善、资源超限、不可比较试验和严格测试污染。
5. 更新时间序列技能、仓库说明、双语安装包、清单和维护文档，物理删除旧 quick/full 技能，不保留兼容壳。
6. 在 `iget` 中恢复并演进公共调参模块时，Transformer 目录只提供候选配方和稳定训练/验证入口；注册制数据边界、比较组、过程分析和继续门禁由公共模块负责。

## 范围

- `SKILLS/zh` 与 `SKILLS/en` 的 PyTorch 调参技能及时间序列技能引用。
- `packages/zh` 与 `packages/en` 的镜像、清单和说明。
- `docs/cx` 当前设计、任务与交付证据。
- 通用轨迹分析脚本及其最窄测试。
- 不改动与调参无关的技能，不在 `cx` 仓库承载具体模型参数。

## 验收

- 仓库中不存在 quick/full 双调参协议或十分之一股票调参语义。
- 中英文只公开一个 PyTorch HPO 技能，源技能与安装包镜像逐字节一致。
- 工具测试覆盖连续业务退化、目标冲突、严格测试污染与继续/停止门禁。
- 中文包、英文包、单一事实来源与发行校验全部通过，`git diff --check` 通过。
- `iget` 后续调参以注册制全部股票为唯一搜索数据边界，并通过公共调参模块和本工具产生可追溯判断；不会预排队自动连续训练。
