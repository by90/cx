## 当前事实

- `$cx-timeseries-modeling` 要求建立简单基线，但没有要求先读取项目正式版本标签及其冻结产物。
- `$cx-pytorch-hpo` 记录验证损失累计严格改进次数，但允许未超过二十次改进的训练参与模型判断和最优候选选择。
- `$cx-pytorch-hpo` 允许剪枝器在训练证据尚未成立时淘汰参数试验，也允许二三十轮后早停的参数试验直接成为最优候选。
- `$cx-review` 没有核对模型实验是否完成正式版本基线比较、训练前研究和训练证据有效性门禁。

## 目标状态

- 时间序列建模和 PyTorch 调参在启动新模型方向前，先读取项目正式版本标签、冻结配置、指标和真实产物，并完成针对当前问题的联网研究。
- 正式版本只通过项目授权的标签和冻结产物读取；不得为了比较基线而恢复工作树、建立工作树副本或重训历史版本。
- 训练只有在验证损失累计严格改进次数至少为二十一次时才成为有效模型证据；不足二十一次的训练不得支持对模型、损失、特征、容量、优化或调度方案的肯定和否定结论，也不得成为基线、最优候选或扩容依据。
- 自动调参的剪枝、采样和最优候选选择不得把未达到有效性门禁的参数试验当作方向证据。
- 统一交付审查显式核对正式基线、训练前研究、二十一次验证损失严格改进和同口径业务指标。

## 主要变化

1. 为 `$cx-timeseries-modeling` 增加正式版本、研究先行和训练证据有效性门禁。
2. 为 `$cx-pytorch-hpo` 增加参数试验有效性、剪枝与最优候选资格规则，并修正与现有 `120/9` 合同的关系。
3. 为 `$cx-review` 增加机器学习实验交付物审查项和完成证据门禁。
4. 让 `$cx-pytorch-hpo` 的双语轨迹分析器计算证据资格，排除不足二十一次严格改进的最优候选和方向性拟合判断。
5. 同步中文源、中文安装包、英文源和英文安装包的同等约束。
6. 更新当前设计和原任务，使正式文档只表达最新规则。
