# 变更：改为逐次诊断驱动的全量调参

## 变更原因

当前 `$cx-pytorch-full-hpo` 预先固定五个候选，并要求不中断地完成全部候选后再分析。这会让高成本全量训练在已经暴露收敛、速度、召回或风险问题时继续消耗时间，也会阻止人工智能代理根据刚完成实验的证据修正下一次配置。

## 当前目标

1. 全量调参使用全部样本，但候选数量不设上限，也不预先建立连续执行队列。
2. 每次只定义、启动、训练、测试和回测一个候选。
3. 单个候选结束或异常中止后立即停止流水线，完成诊断并形成下一次唯一实验假设。
4. 只有诊断证据支持下一次调整时，才允许另外启动一个候选；禁止后台流程自动进入预先安排的下一项。
5. 训练轮数、提前停止忍耐轮数、固定维度和可调整维度服从用户当前任务；技能默认值不得覆盖用户明确配置。

## 强制诊断范围

每次候选结束后必须立即分析并保存以下事实：

1. 未跑满原因：区分提前停止、异常、资源不足、人工中止和正常完成，追踪提前停止监控值、最小改进量、忍耐轮数、学习率阶段、最后改善轮次和检查点状态。
2. 损失下降缓慢原因：比较训练损失与验证损失曲线、最佳轮次、改善间隔、实际学习率、梯度、有效批量、每轮优化步数、欠拟合、过拟合、噪声和容量限制。
3. 训练速度原因：拆分数据准备、训练批次、验证批次、回测和保存耗时，核对样本吞吐、批次数、图形处理器利用率、显存、系统内存、进程内存、数据加载、输入输出和计算瓶颈。
4. 召回率低原因：先核对标签定义、正类基数、每日正类数量和时间切分，再检查混淆矩阵、精确率—召回率曲线下面积、正类召回率、每日前十召回率、每日前十精确率、覆盖率、分数分布、阈值与排序的区别、假阴性和假阳性样本。
5. 业务风险：检查每日前十中的大跌数量与占比、收益分位数、最差收益、尾部平均损失、命中与未命中的收益差异，不能只报告平均收益或普通准确率。
6. 数据与实现正确性：核对字段语义、缺失和异常分布、归一化冻结、标签泄漏、窗口和时间边界、类别权重或采样、随机种子、恢复状态、检查点与产物完整性。
7. 比较有效性：核对候选之间唯一改动、指标口径、数据成员和验证频率；严格测试或回测参与选择时明确记录选择偏差，不能称为未触碰留出集上的无偏结论。
8. 下一次决策：写出一个可证伪的主要原因、支持与反对证据、下一次唯一最小改动、保持不变的配置、预期改善指标和停止条件。证据不足时先补诊断，不得盲目再训。

## 工作顺序

1. 先修改中文技能、中文路由说明和中文安装包镜像。
2. 审查中文表达是否彻底删除固定五候选和连续自动执行语义。
3. 同步英文技能、英文路由说明和英文安装包镜像。
4. 更新当前设计和原任务文档。
5. 运行双语技能包、安装包、单一事实来源、编码、差异和技能结构验证。
6. 使用 `$cx-review` 连续完成交付物质量审查和完成证据门禁。
7. 审查通过后删除本变更文件并提交，推送 `main`，再从远端运行中文安装脚本并核对本机技能。

## 验证方式

- 搜索固定五候选、自动继续其余候选、全部候选完成后才分析等失效语义。
- 检查中英文技能都明确每次只运行一个候选、结束后立即诊断和禁止预先队列。
- 检查诊断产物覆盖收敛、速度、召回、业务风险、数据正确性、比较有效性和下一次决策。
- 运行仓库现有双语包和单一事实来源验证工具。
- 使用技能结构验证工具检查中英文 `SKILL.md`。
- 运行 `git diff --check` 并检查所有变更文件编码。
