# 变更：改为逐次诊断驱动的全量调参

## 当前事实

当前安装版本的 `$cx-pytorch-full-hpo` 预先固定五个候选，并要求不中断地完成全部候选后再统一分析。快速调参技能也把五个轻量候选直接表达为交给全量调参的执行集合。高成本全量训练即使已经暴露收敛、速度、召回或风险问题，仍可能继续执行预先安排的其余候选。

## 目标状态

1. 全量调参使用任务定义的全部样本，但候选数量不设上限，也不预先建立连续执行队列。
2. 每次只定义、启动、训练、测试和回测一个候选。
3. 完整训练、测试和回测链结束，或者任一阶段异常中止后，立即停止流水线并完成诊断。
4. 只有诊断证据支持一个可证伪原因和下一次唯一最小改动时，才允许启动另一个候选。
5. 训练轮数、提前停止忍耐轮数、固定维度和可调整维度服从用户当前任务；技能默认值不得覆盖用户明确配置。
6. 快速调参的五个最终候选只作为全量调参可读取的初始证据，不构成必须连续执行的候选队列。

## 主要变化

1. 删除全量调参固定五候选、轻量调参强制准入、只允许调整训练参数、全部完成后统一分析和自动继续其余候选的规则。
2. 新增每次一个全量候选、结束后强制暂停、候选数量不设上限和证据驱动下一次实验的规则。
3. 每次候选结束后必须立即诊断：
   - 未跑满原因，包括提前停止、异常、资源不足、人工停止、学习率阶段、最后改善轮次和检查点状态；
   - 损失下降缓慢原因，包括训练与验证曲线、实际学习率、梯度、有效批量、优化步数、欠拟合、过拟合、噪声和容量；
   - 训练速度，包括数据准备、训练、验证、测试、回测和保存耗时，样本吞吐、图形处理器、显存、系统内存、进程内存、数据加载和输入输出；
   - 召回与排序覆盖，包括标签定义、正类基数、每日正类分布、混淆矩阵、精确率—召回率曲线下面积、正类召回率、每日前若干名召回率、精确率、覆盖率、分数分布和阈值；
   - 业务风险，包括大跌数量与占比、收益分位数、最差收益和尾部平均损失；
   - 数据、实现和比较正确性，包括字段语义、归一化、泄漏、窗口、时间切分、种子、恢复、检查点、指标对齐和严格测试参与选择的偏差。
4. 下一候选必须登记一个可证伪主要原因、支持与反对证据、唯一主要改动、必需耦合改动、保持不变的配置、预期指标、风险护栏和停止条件。
5. 同步中文源、中文安装包、英文源、英文安装包、时间序列技能路由、项目说明、设计和原任务当前状态。
