## 当前实现要求

- 先完成中文源和中文包，再同步英文源和英文包。
- `$cx-doc` 的双语技能资产提供结构等价的默认项目 `AGENTS.md` 模板，并随技能镜像安装。
- 中英文示例项目都提供按真实目标、语言工具链和通用包填写的根目录 `AGENTS.md`，并包含可执行的通用包教程。
- 包清单包含 `$cx-doc` 和唯一交付审查入口 `$cx-review`。
- 单一来源校验器识别 `docs/cx/docs/`、`docs/cx/notes/` 和当前临时变更结构。
- `$cx-tdd` 承担唯一测试先行主流程；`$cx-pytorch-tdd` 和 `$cx-rust-tdd` 只补充各自语言的工具、布局、真实数据夹具和特有检查。
- 测试禁止表达式与表达式比较，也禁止完整有序集合的列表式比较；默认分别检查首项、末项和一个中间项，右侧使用已确认常量。
- Python 数据测试由 `tests/__init__.py` 一次读取测试数据库并共享真实对象；Rust 数据测试由统一夹具模块使用一次初始化机制共享真实对象。
- 除非用户当前请求明确要求，Python 和 Rust 测试都禁止使用模拟对象或伪造数据访问层。
- `$cx-pytorch-tdd`、`$cx-pytorch-quick-hpo` 和 `$cx-pytorch-full-hpo` 把系统内存与显存评估作为任何实验训练的第一道门禁，启动前记录预计峰值和安全余量。
- 预计资源占用较多或耗时较长的训练在 Codex App 之外的外部终端启动，持续写入文件型日志；人工智能代理通过读取日志文件分析，不依赖终端特殊处理。
- `$cx-pytorch-quick-hpo` 表达快速调参：固定使用十分之一完整实体样本，统一按 `120` 个训练轮次规划，默认提前停止忍耐轮数为 `20`，配置种子为 `3407`；先把每个维度标记为用户固定、参与搜索或有证据排除，所有实际字段保留语义与泄漏检查，用户固定的特征和参数不进入搜索、长窗口扩展或消融，未固定范围至少考虑模型结构、学习率范围、优化器、调度器和滑动窗口等样本特性；窗口允许搜索时先在 `3–20` 天内形成初选五候选，再对初选最强候选执行 `30`、`40`、`50`、`60` 天扩展并联合复跑五个最终完整参数组合；最终候选分别完成消融实验和回测。
- `$cx-pytorch-full-hpo` 固定使用全部样本，统一按 `120` 个训练轮次规划，默认提前停止忍耐轮数为 `20`，配置种子为 `3407`；保持快速阶段最终确定的数据参数、标签、窗口和模型结构不变，只调整批次大小、学习率、优化器参数和调度器参数，并逐一训练、测试和回测 `5` 个候选。
- 快速调参只在同一标签、验证集、损失定义、验证频率、有效改进阈值和训练上限组成的可比组内，以四项联合目标作为筛选五候选的最高优先级：最佳验证损失 `best_val_loss` 较小、验证损失 `val_loss` 有效改进次数较多、完成轮次尽量接近第 `120` 轮、从 `1` 开始编号的最佳轮次尽量靠近第 `120` 轮。任何单项不得独自决定晋级；测试损失 `test_loss`、回测结果、训练速度和资源利用率只负责泛化确认、业务确认和执行约束。
- 快速和全量调参使用学习率升温和降温循环时，必须保存调度器名称、升温轮数、降温轮数、循环次数、最高学习率、最低学习率、变化函数和实际忍耐轮数；只有单个完整循环超过 `20` 轮时才调整忍耐轮数，并优先选择不超过 `30` 轮的值。
- 全量正常候选必须跑满 `120` 个训练轮次，并在第 `101` 至 `120` 轮出现新最佳验证损失；全部五候选都不满足时才按完成轮数和最后 `20` 轮改进回退。该资格只用于全量阶段，不得反向取消快速调参候选或跳过任何候选的训练、测试和回测。
- 所有编码规则绝对禁止顺手处理当前任务之外的问题；任务范围由用户当前请求、当前用例路径、原任务和未完成变更共同界定。
- 任务外问题只能列入包含文件、位置、现象、风险和建议的待授权清单；只有用户对具体清单项明确授权后才能修改，代理推测和审查意见不构成授权。
- 安装脚本继续从远端 `main` 更新全局技能和 `AGENTS.md`。
