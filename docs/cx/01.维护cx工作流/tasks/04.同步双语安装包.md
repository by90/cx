# 任务 04：同步双语安装包

## 来源

- 用例文件：`../00.用例.md`
- 设计文件：`../00.设计.md`
- 对应用例路径：主成功场景第 4 至 6 步

## 目标

让中文源、英文源、安装包、模板、说明、全局规则和项目 `AGENTS.md` 模板表达同一套当前流程。

## 文件范围

- 公共技能源：`SKILLS/zh/`、`SKILLS/en/`
- 中文包：`packages/zh/`
- 英文包：`packages/en/`
- 项目说明：`README.zh-CN.md`、`README.md`
- 流程校验入口：`packages/zh/tools/validate_single_source.py`，英文包保存等价实现
- 单元测试文件：无；`cx` 源仓库禁止创建、维护或运行单元测试。

## 任务量具

- 规则组：双语技能集合、包清单、模板、安装后全局规则、项目规则模板、项目说明

## 当前实现要求

- 先完成中文源和中文包，再同步英文源和英文包。
- `$cx-doc` 的双语技能资产提供结构等价的默认项目 `AGENTS.md` 模板，并随技能镜像安装。
- 中英文示例项目都提供按真实目标、语言工具链和通用包填写的根目录 `AGENTS.md`，并包含可执行的通用包教程。
- 包清单包含 `$cx-doc` 和唯一交付审查入口 `$cx-review`。
- 单一来源校验器识别 `docs/cx/docs/`、`docs/cx/notes/` 和当前临时变更结构。
- `$cx-tdd` 承担唯一测试先行主流程；`$cx-pytorch-tdd` 和 `$cx-rust-tdd` 只补充各自语言的工具、布局、真实数据夹具和特有检查。Rust 生产源码绝对禁止测试代码，根目录 `tests/` 尽可能镜像 `src/`，一个被测源码文件最多对应一个同名 `_test.rs`。
- `$cx-ui` 是页面、组件、ViewModel、界面状态和 UI 巨型文件的专用入口，固定 View → ViewModel → Service → Data 单向依赖；每个页面、组件和 ViewModel 分别位于独立文件，模块入口只负责装配与导出。
- 测试禁止表达式与表达式比较，也禁止完整有序集合的列表式比较；默认分别检查首项、末项和一个中间项，右侧使用已确认常量。
- Python 数据测试由 `tests/__init__.py` 一次读取测试数据库并共享真实对象；Rust 数据测试由统一夹具模块使用一次初始化机制共享真实对象。
- 除非用户当前请求明确要求，Python 和 Rust 测试都禁止使用模拟对象或伪造数据访问层。
- `$cx-pytorch-tdd` 和 `$cx-pytorch-hpo` 都把系统内存与显存评估作为任何实验训练的第一道门禁。`$cx-pytorch-hpo` 进一步核对中央处理器、物理内存、系统提交内存与逐卡显存，并按最近可比实测峰值记录新增占用预算和安全余量。
- 预计资源占用较多或耗时较长的训练在 Codex App 之外的外部终端启动，持续写入文件型日志；人工智能代理通过读取日志文件分析，不依赖终端特殊处理。
- `$cx-pytorch-hpo` 是唯一调参入口，要求复用目标项目的模型无关公共调参模块。模型目录只提供网络、损失和条件搜索空间，不复制持久化 study、采样、剪枝、恢复和分析生命周期。
- `$cx-pytorch-hpo` 的逐轮训练报告固定包含当前轮次/最大轮次、验证损失累计严格改进次数、当前早停计数/早停忍耐、训练集轮均损失和验证集损失；验证损失改进次数与项目验证选择目标的早停计数分别记录。
- study 启动前通过项目损失权威入口冻结无信息理论基准损失、理论下界、公式、损失报告精度和平台观察窗口。参数试验结束后报告最小验证损失相对理论基准的绝对改善、相对改善百分比和可改善损失完成率；不可定义时明确报告不可用，不猜测数值。
- 股票排名任务逐轮和结束报告动态 TopN、固定 Top1、Top3 和 Top10。动态 TopN 在样本范围、目标日期、机会语义和聚合方式一致时作为不同标签刻度的统一业务比较标准，同时报告刻度、机会定义和每日 N 来源。
- 每个参数试验结束后由代理人工阅读完整训练与验证损失轨迹，判断过拟合、欠拟合、拟合健康或证据不足，并按冻结精度和观察窗口记录 `plateau_start_epoch`、区间及证据。训练完善度、业务报告和拟合诊断默认不改变冻结的选择、剪枝、早停、检查点和严格测试合同。
- 产品默认配置、模型公共代码和训练公共代码不因参数试验改写。调参脚本为每个参数试验复制类型化配置，只在内存覆盖 sampler 当前提议的搜索维度，把实际配置显式传给现有模型和训练入口，并在启动边界冻结该参数试验自己的实际配置快照。
- study 冻结数据、标签、验证业务目标、`120/9` 合同、资源策略、条件搜索空间和禁止搜索项，不把待搜索参数预先冻结成全部参数试验共用的一组值。
- 股票任务固定使用注册制起点后的全部合格实体和全部合格日线，不使用十分之一实体，也不切换到注册制以前历史。创业板默认起点为 `2020-08-24`，项目经审计事实优先。
- 高资源工作包括训练工作进程、完整测试、回测、分析器和会大量载入数据的诊断进程。高资源工作默认串行，同时运行绝不超过两个；每张显卡同时只运行一个独立参数试验工作进程。
- 启动调参研究、训练工作进程领取新参数试验或启动任何高资源辅助进程前，重新读取中央处理器负载及重进程、物理内存总量与可用量、Windows 已提交字节与提交上限、逐卡显存总量与可用量、占卡进程和当前高资源工作数。只有新增峰值预算与安全余量在所有维度都能满足时才准入。
- 双卡并行只在主机内存、提交内存和两张显卡均通过容量门禁时启用，一张卡一个参数试验工作进程，并占满两个并发名额；此时不得再并行启动完整测试、回测、分析器或其它高资源工作。容量不足时等待或恢复串行，不缩小注册制数据，不盲目重试。
- 训练期间按固定采样间隔把中央处理器、物理内存、提交内存和逐卡显存快照与峰值写入文件型轨迹；每次增加进程前仍需重新准入，已有负载上升或余量不足时停止派发新工作。
- 采样器可以持续提出联合配置，剪枝器根据逐轮验证业务指标自主剪枝。代理不得人工预排、覆盖下一配置或用严格测试改变方向。
- 普通单候选基线、复现、可证伪实验和正式自动 HPO trial 都最多训练一百二十轮；项目验证选择目标连续九个完整训练轮未刷新时早停，不设置必须完成一百轮的最低门槛。
- `120/9` 早停的最低提高量固定为零；验证选择目标只要出现任何严格提高，九轮忍耐计数立即归零。
- 正式自动 HPO 的成熟 sampler/pruner 联合提出参数并按逐轮验证业务指标更早淘汰相对劣势 trial；pruner 不得取消、替代或延长单个 trial 的 `120/9` 规则。
- 自然完成 120 轮是独立跑通目标，不能延迟或关闭九轮早停、扩大忍耐、设置最低轮次门禁或关闭剪枝来达成。incumbent 始终只按验证业务指标选择；二三十轮后早停的 `complete` 参数试验仍可成为 incumbent。
- 损失改善而业务指标显著退化，或两个连续可比候选的业务指标显著低于基线时，轨迹分析必须返回停止；只有一个可证伪假设和一个唯一最小改动成立时才返回继续。
- 严格测试可以审计最终冻结配方，但不得进入候选选择或下一改动；一旦参与选择，明确污染并停止。
- 中英文统一技能都附带 `scripts/analyze_hpo_progress.py`，输出机器可读 JSON 与 Markdown，识别注册制范围、严格测试污染、可比组、连续业务退化、目标冲突、多项改动、无有效改善和资源失败。
- 所有编码规则绝对禁止顺手处理当前任务之外的问题；任务范围由用户当前请求、当前用例路径、原任务和未完成变更共同界定。
- 任务外问题只能列入包含文件、位置、现象、风险和建议的待授权清单；只有用户对具体清单项明确授权后才能修改，代理推测和审查意见不构成授权。
- 安装脚本从远端 `main` 取得当前语言的权威技能集合，每次逐个卸载全部同名 cx 技能，再完整安装全部技能，不依据既有安装清单哈希省略技能。
- 安装脚本完成前逐个核对远端源技能与全局技能的文件集合和文件哈希，并核对全局 `AGENTS.md` 与当前语言包模板的文件哈希。
- 双语安装包不保留 `tests/` 目录或单元测试文件；发行验证器不得调用 `unittest` 或其它单元测试框架。

## 验证方式

- 运行中文包和英文包验证工具。
- 比较公共技能源与安装包镜像。
- 比较 `$cx-doc` 双语项目规则模板资产与安装包镜像。
- 快速校验中英文 `$cx-tdd`、`$cx-pytorch-tdd`、`$cx-pytorch-hpo`、`$cx-rust-tdd`、`$cx-ui` 和 `$cx-workflow` 技能目录。
- 搜索 Rust 生产源码测试禁令、`src`/`tests` 镜像的一对一文件映射、UI 四层单向依赖和页面、组件、ViewModel 单文件门禁，确认中英文语义等价。
- 搜索主流程重复、旧 Rust 路由、`pytest`、重复数据库读取和默认模拟测试等冲突说法。
- 搜索两个 PyTorch 技能的资源安全门禁、外部终端和文件型日志规则，确认物理内存与提交内存分别核对、默认串行、最多两个高资源工作、双卡占满并发名额、辅助进程重新准入和中英文语义等价。
- 搜索统一调参技能是否只让调参脚本复制类型化配置、在内存覆盖 sampler 提议并显式传入现有入口；确认产品默认配置、模型公共代码和训练公共代码不因参数试验改写；核对普通单候选和正式自动 HPO trial 的 `120/9` 停止规则、业务 incumbent 与自然跑通双目标、公共模块复用、完整条件空间、严格测试隔离和 trial 分析。
- 搜索统一调参技能的逐轮训练报告、无信息理论基准与损失完善度、动态 TopN 与固定 Top1/Top3/Top10、人工拟合判断和平台开始轮次，确认报告字段与冻结选择目标相互隔离，并核对中英文语义等价。
- 静态核对中英文轨迹分析工具的当前停止合同，并比较源技能与安装包的完整目录而不只比较 `SKILL.md`。
- 搜索全局规则、`$cx-workflow` 和 `$cx-review` 的任务边界、绝对禁止、待授权清单和明确授权规则，确认中英文语义等价。
- 在隔离目标目录连续运行中文和英文安装脚本，确认每次都完整重装十五个技能，并逐个比较文件集合和文件哈希。
- 推送 `main` 后运行中文安装脚本并核对安装结果。
