# 设计：维护 cx 工作流

## 文件范围

- 中文技能源：`SKILLS/zh/`
- 英文技能源：`SKILLS/en/`
- 安装包镜像：`packages/zh/`、`packages/en/`
- 项目规则：根目录 `AGENTS.md`、`$cx-doc` 的双语 `assets/AGENTS.md`
- 项目级说明：`README.zh-CN.md`、`README.md`

## 功能入口

- `$cx-workflow`：先读取项目 `AGENTS.md` 和当前领域教程并搜索已登记通用能力，再分流当前工作。
- `$cx-story`：维护唯一当前用例、设计和固定任务集合。
- `$cx-changelog`：登记、提交和删除临时变更文件。
- `$cx-doc`：维护通用包调用者教程、专题文档、研究笔记和项目 `AGENTS.md` 教程导航。
- `$cx-tdd`：统一执行所有语言的测试先行主流程和断言纪律。
- `$cx-pytorch-tdd`：只补充 Python、PyTorch 和 Lightning 的测试工具、布局、共享真实数据和张量检查。
- `$cx-pytorch-quick-hpo`：快速调参固定使用十分之一完整实体样本，统一按 `120` 个训练轮次规划，默认提前停止忍耐轮数为 `20`，配置种子为 `3407`；冻结用户明确固定的维度，搜索其余模型结构、学习率范围、优化器、调度器和滑动窗口等重要维度；窗口允许搜索时先在 `3–20` 天内形成初选五候选，再对初选最强候选执行 `30`、`40`、`50`、`60` 天扩展并联合复跑五个最终完整参数组合；最终以较小验证损失、较多验证损失有效改进次数、完成轮次尽量接近 `120` 和最佳轮次尽量靠近第 `120` 轮的四项联合目标筛选 `5` 个候选，并分别执行消融实验和回测。
- `$cx-pytorch-full-hpo`：全量调参使用全部样本，每次只运行一个候选；候选结束后立即诊断未跑满原因、损失下降缓慢、训练速度、召回与排序覆盖、业务风险、数据正确性和比较有效性，再依据证据决定下一次唯一调整。候选数量不设上限，禁止预先建立连续执行队列；训练轮数、提前停止忍耐轮数、固定维度和可调整维度服从用户当前任务，用户未指定时才使用技能默认值。
- `$cx-rust-tdd`：只补充 Rust 内置测试、共享真实数据夹具和 `cargo` 检查。
- `$cx-review`：执行交付物质量审查和完成证据门禁。

## 可复用能力

- 复用现有双语技能目录、包清单和安装脚本。
- 复用 `$cx-doc` 技能资产分发默认项目 `AGENTS.md` 模板，不建立第二份安装模板。
- 复用现有 `changes/` 文件结构承载当前工作指令。
- 复用 `cx-review` 审查代理执行统一交付审查。

## 设计决策

| 决策 | 理由 | 影响 |
| --- | --- | --- |
| 正式文档只写当前状态 | 避免人工智能代理读取失效方案 | 未完成变更文件只服务当前工作 |
| 已有 story 的任务文件身份固定 | 避免同一工作产生大量增删改任务 | 实现方式变化时原地修改任务正文 |
| 完成后删除变更文件 | Git 已保存变更登记和删除历史 | `changes/` 只显示当前未完成工作 |
| 一个技能承担完整审查 | 保持单一审查入口 | `$cx-review` 使用两个连续审查阶段 |
| 通用包教程集中在 `docs/cx/docs/` | 让调用者从真实目标、入口和步骤理解现有能力 | 每个通用包拥有独立编号教程，其它文档只链接 |
| 项目 `AGENTS.md` 导航领域教程 | 让全局规则与项目事实分离，并在实现前完成知识门禁 | 模板随 `$cx-doc` 分发，项目按目标、语言、工具链和通用包填写 |
| 研究结论集中在 `docs/cx/notes/` | 让研究回答具体问题并可复用 | 研究笔记使用流畅中文和必要来源 |
| `$cx-tdd` 统一测试先行流程 | 避免语言技能重复并分叉测试步骤和断言规则 | 语言技能只保留工具链、布局、真实数据夹具和语言特有检查 |
| 测试期望值只使用常量事实 | 避免测试重复实现生产表达式或整表比较 | 有序集合只检查首项、末项和一个中间项，除非用户明确要求全量验证 |
| 数据测试集中加载真实测试数据库 | 避免每个测试重复读取或用模拟数据替代业务事实 | Python 在 `tests/__init__.py` 初始化，Rust 在统一夹具模块中一次初始化 |
| 实验训练先执行资源安全门禁 | 避免系统内存、显存或终端输出负载造成系统崩溃，尤其避免 Codex App 崩溃 | 启动前记录资源估算和安全余量，高资源或长耗时任务使用外部终端与文件型日志；资源与速度只确定安全范围和实验预算，不替代候选目标 |
| 全量调参由单次证据驱动下一次实验 | 完整数据训练成本高，前一候选已经暴露的收敛、速度、召回或风险问题必须先解释 | 轻量阶段结果可以作为初始证据但不是固定数量准入；全量阶段每次只运行一个候选，结束后强制诊断，再决定下一次唯一改动 |
| 快速调参先划定固定与搜索维度 | 用户已经确定的特征或参数不应消耗试验预算，固定一项也不应连带冻结其它维度 | 每个维度标记为用户固定、参与搜索或有证据排除；未固定范围至少考虑模型结构、学习率范围、优化器、调度器和滑动窗口等样本特性 |
| 五候选使用四项联合最高优先级目标 | 单次最低损失、单次高回测、训练速度或过早停止后的短距离都不能证明候选质量 | 联合比较最佳验证损失、有效改进次数、完成轮次距第 `120` 轮的距离和最佳轮次距第 `120` 轮的距离；测试损失、回测和资源指标只负责确认或约束 |
| 不可比损失口径分别筛选 | 不同标签、类别数或损失定义的验证损失不能直接排序 | 先确定标签和损失口径，再在同一可比组内按四项联合目标筛选五候选 |
| 分阶段搜索结束后联合复跑 | 窗口、批次、学习率、优化器、调度器和模型结构存在相互影响 | 阶段结果只缩小范围，最终候选使用完整参数组合联合复跑，不永久锁死早期单点结果 |
| 快速调参窗口分成基础搜索与条件扩展 | 长窗口显著改变显存、训练耗时和批次预算，用户固定窗口也不应被自动改变 | 窗口允许搜索时先在 `3–20` 天内形成初选五候选，再对初选最强候选执行四次长窗口扩展；窗口变化后联合复跑五个最终完整参数组合，窗口固定时全部跳过 |
| 循环学习率与提前停止共同配置 | 升温和降温循环尚未完成就提前停止会错误淘汰候选 | 默认忍耐轮数为 `20`；循环调度显式保存完整参数，只有单个循环超过 `20` 轮时才调整忍耐轮数并尽量不超过 `30` |
| 快速与全量调参使用不同推进方式 | 快速阶段需要用固定样本预算比较多个方案，全量阶段需要及时解释高成本实验 | 快速阶段按四项联合目标筛选五候选；全量阶段不固定候选数和准入队列，每个候选训练、测试和回测后立即停止并完成六类诊断，只有一个可证伪原因和最小改动成立时才启动下一候选 |
| 绝对禁止顺手处理任务外问题 | 防止代理把推测、偏好或审查意见误当成用户需求 | 任务外问题只进入待授权清单，用户对具体清单项明确授权后才能修改 |

## 非目标

- 不保存完成变更档案。
- 不为同一任务建立“新增”“修改”“删除”任务链。
- 不设置第二个交付审查入口。
- 不把专题知识重复写入任务、变更和包内说明。
- 不在项目 `AGENTS.md` 复制全局规则或保留未填写模板项。
- 不把代理发现的任务外问题自动纳入实现、清理或审查修复范围。

## 验证方式

- 校验中文和英文技能集合一致。
- 校验 `$cx-doc` 的双语项目规则模板资产与安装包镜像一致。
- 校验项目 `AGENTS.md` 覆盖项目目标、语言工具链、全部通用包教程链接和领域先读门禁。
- 校验安装包清单与技能目录一致。
- 校验仓库只有 `$cx-review` 一个交付审查技能入口。
- 校验 `$cx-tdd` 是唯一测试先行主流程，两个语言技能没有复制主流程。
- 校验测试断言、真实数据库共享和默认禁止模拟测试的中英文规则等价。
- 校验三个 PyTorch 技能都先执行内存与显存评估，并统一使用外部终端和文件型日志承载高资源或长耗时训练。
- 校验快速调参技能的中英文约定包含 `120` 个训练轮次、默认提前停止忍耐轮数 `20`、配置种子 `3407`、十分之一完整实体样本、用户固定维度、全部实际字段语义与泄漏检查、模型结构、学习率范围、优化器、调度器、同一可比组、有效改进阈值、四项联合最高优先级目标、窗口分阶段搜索、五个最终候选、逐候选消融和逐候选回测；校验全量调参中英文约定包含全部样本、用户配置优先、每次一个候选、候选数不设上限、禁止预先队列、立即同源测试回测、六类强制诊断、下一次唯一最小改动和严格测试参与选择时的偏差声明。
- 校验全局规则、`$cx-workflow` 和 `$cx-review` 绝对禁止顺手处理任务外问题，并要求待授权清单和用户具体授权。
- 搜索正式文档中是否要求保存完成变更或过程差异。
- 运行项目现有包验证工具；本次未声明单元测试。
