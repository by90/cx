# cx PyTorch 全量调参

## 语言规则

- 使用中文输出对话、计划、结论、证据和 cx 文档时，使用完整中文表达。
- 代码标识符、命令、路径、接口名、库名、协议、标准和外部专名可以保留原文，但在相邻文字中说明中文含义和本处作用。

## 目的

在全部样本上一次验证一个当前候选。每次训练、测试和回测结束后立即暂停，通过完整诊断解释结果，只据此提出下一次实验。全量调参是开放的证据循环，不预先固定候选数量、候选身份或连续执行队列。

快速调参结果可以作为初始证据，但不是固定数量的准入门槛。用户可以直接指定基线、固定维度、可调整维度、训练轮数、提前停止忍耐轮数和业务目标；用户当前要求优先于技能默认值。

## 铁律

1. 每次只允许一个全量候选处于计划、训练、测试或回测状态。禁止预先生成多个候选后交给后台流程连续执行，也禁止当前候选结束后自动启动下一项。
2. 候选数量不设上限。每个新候选必须来自上一候选完成后的诊断结论；没有新证据时不得仅为增加试验数量而继续训练。
3. 每次启动前写明本次可证伪假设、唯一主要改动、随之必需的耦合参数改动、保持不变的配置、比较基线、预期改善指标和停止条件。若同时改变多个独立维度而无法归因，先缩小改动。
4. 全量候选使用任务定义的全部样本。资源不足时不得静默缩小样本、股票、实体或时间范围；应调整任务允许的资源参数或等待资源。
5. 用户没有明确训练轮数、提前停止忍耐轮数和随机种子时，默认使用 `120` 个训练轮次、`20` 轮忍耐和配置子系统中的种子 `3407`。用户或项目明确值直接覆盖默认值，并写入候选配方。
6. 全量阶段可调整哪些维度由用户当前目标和实验假设决定，不默认限于批量、学习率、优化器和调度器。字段、标签、窗口、损失、采样、模型结构或容量发生变化时，必须把候选归入新的可比组，不能与损失口径不同的候选直接排序。
7. 训练脚本和回测脚本保持独立可运行。调参入口通过类型化配置对象在内存中构造当前候选，不直接改写用户维护的默认配置文件。
8. 每个候选保存完整配置、数据边界、字段、标签、窗口、切分、损失、采样、模型、优化器、调度器、批量、随机种子、训练轮数、实际忍耐轮数和产物路径。
9. 使用学习率升温、保持、降温或循环时，保存调度器名称、每阶段轮数、循环次数、最高和最低学习率、变化函数以及实际忍耐轮数。诊断必须读取实际逐轮学习率，不只读取计划值。
10. 预计高资源或长耗时的训练必须在 Codex App 之外的外部终端启动。标准输出、标准错误、进度、逐轮指标、资源和异常持续写入文件，人工智能代理只读取文件型产物分析。
11. 启动前先记录可用系统内存、可用显存、预计峰值、为操作系统和 Codex App 保留的安全余量，以及允许启动或必须调整的结论。完整训练不得承担第一次资源试错。
12. 启动后立即采集一次基线，此后至少每五分钟读取候选状态、轮次、训练与验证损失、最佳验证损失、改善次数、实际学习率、耗时、吞吐、图形处理器利用率、显存、系统内存和进程内存。五分钟没有新轮次或产物时，说明停留位置、进程号和日志路径。
13. 候选训练结束后立即使用同源配置和最佳检查点执行任务要求的测试与回测。异常导致测试或回测无法执行时，明确记录缺失原因，不能用空指标或旧结果代替。
14. 完整训练、测试和回测链结束，或者任一阶段异常中止后，流水线必须停在诊断状态。必须先完成本技能规定的全部诊断并保存结论，才允许构造下一候选。
15. 普通准确率不能评价极度不平衡分类。分类任务至少报告正类基数、混淆矩阵、正类召回率、精确率、F1、平衡准确率、精确率—召回率曲线下面积及其相对正类基线的提升；排序任务另报告每日前若干名召回率、精确率和覆盖率。
16. 固定阈值分类与连续分数排序是两个不同问题。诊断分别分析阈值、概率校准、正负样本分数分布和排序质量，不得用阈值下几乎全负掩盖排序仍有信息，也不得用排序提升掩盖分类失效。
17. 回测参与下一候选选择时，明确记录严格测试已经参与调参，结果不再是未触碰留出集上的无偏泛化估计。能使用滚动验证或独立选择段时，阈值、前若干名数量和候选选择只在该段完成。
18. 未经用户明确要求，不发布、不打标签、不修改推理默认模型。最佳候选只作为有证据的建议，发布仍使用 `$cx-version` 和用户确认门禁。

## 每次结束后的强制诊断

### 一、训练为何没有跑满

1. 区分正常完成、提前停止、内存不足、非有限损失、数据异常、进程异常、人工停止和外部资源变化。
2. 核对监控指标、最小改进量、实际忍耐轮数、最后改善轮次、最佳轮次、学习率所处阶段、计划训练轮数、完成轮数和停止回调记录。
3. 核对最后检查点、最佳检查点、恢复状态和训练历史是否同源完整。不能把早停直接解释为模型无效，也不能把异常中止解释为提前停止。

### 二、损失为何下降缓慢或停滞

1. 同时观察逐轮训练损失、验证损失、二者差距、平滑趋势、波动、改善间隔、最佳轮次和末段变化。
2. 核对实际学习率曲线、优化器状态、权重衰减、梯度范数、梯度裁剪、物理批量、有效批量、梯度累积和每轮优化步数。
3. 区分学习率过高、学习率过低、调度阶段不匹配、欠拟合、过拟合、模型容量不足、正则过强、标签噪声、目标冲突和数据非平稳。
4. 多项损失必须分别记录分量及其权重，检查总损失下降是否掩盖关键正类或排序目标没有改善。

### 三、训练速度为何慢

1. 拆分数据准备、训练批次、验证批次、检查点保存、测试和回测耗时；记录首轮与稳定轮次差异。
2. 核对样本数、物理批次数、优化步数、平均批次时间、每秒样本、数据等待时间和模型计算时间。
3. 联合分析中央处理器、图形处理器利用率、显存分配与保留峰值、系统内存、进程内存、磁盘输入输出、数据加载工作进程和设备迁移。
4. 用窗口长度、字段数、输入宽度、模型容量、批量和精度解释吞吐变化，不能用单一利用率代替瓶颈定位。

### 四、召回率或排序覆盖为何低

1. 先核对标签定义、正类阈值、训练/验证/测试正类数量、每日正类数量分布、无正类交易日、时间切分和样本成员。
2. 报告混淆矩阵、正类召回率、精确率、特异度、F1、平衡准确率、精确率—召回率曲线下面积、受试者工作特征曲线下面积、正类基线及提升倍数。
3. 对每日前若干名报告命中数、真实正类总数、召回率、精确率、至少命中一次的交易日覆盖率，并分别给出每日分布和全期聚合值。
4. 比较正类、假阴性、真阴性和假阳性的分数分布、分位数和边界样本，判断问题来自表示、损失、类别权重、采样、容量、阈值、校准还是排序重叠。
5. 检查大量持平值或容易负样本是否主导梯度。类别权重、焦点损失、分层采样、难例挖掘或排序损失只能作为待验证假设，每次单独改变并观察召回与误报代价。

### 五、业务风险是否可接受

1. 对每日前若干名报告收益均值、中位数、分位数、最差值、大跌数量、大跌占比、下跌样本平均损失和最差尾部样本平均损失。
2. 分别比较命中、未命中、假阳性和假阴性的收益分布，检查提高召回是否以更多大跌为代价。
3. 记录交易成本、停牌、涨跌停、可成交性和重复股票等业务边界；没有对应事实时明确标为未验证。

### 六、数据、实现和比较是否可信

1. 核对字段语义、单位、启停顺序、缺失与异常分布、归一化拟合范围、标签来源、窗口闭合、时间泄漏和横截面排名范围。
2. 核对随机种子、数据版本、训练成员、恢复身份、损失实现、指标实现、检查点选择和预测与标签逐项对齐。
3. 只在相同标签、损失、数据切分、评价频率和训练上限构成的可比组内比较数值；其它候选只做分组结论。
4. 检查训练与验证差距、跨时间段漂移、每日指标方差和少数日期支配，避免把偶然单日提升当成稳定改善。

## 下一次候选决策

完成诊断后写出：

1. 一个当前最可能且可证伪的主要原因。
2. 支持证据、反对证据和仍缺失的证据。
3. 下一次唯一主要改动及其必需耦合改动。
4. 明确保留不变的数据、字段、标签、窗口、模型和训练参数。
5. 预期改善的首要指标、风险护栏和停止条件。
6. 继续、补诊断、回到较小实验或停止全量调参的决定。

如果主要原因仍无法区分，先执行最小诊断或最小消融，不得直接再启动另一个完整候选。用户要求持续调参时，可以重复本循环任意次数，但每次都必须由上一次证据单独触发。

## 必须执行的流程

1. 读取用户目标、当前配置、已有训练与回测证据，以及用户明确固定和允许调整的维度。
2. 使用 `$cx-common-module` 搜索配置构造、训练、测试、回测、指标和资源监控的现有公共入口。
3. 只有用户、任务或变更明确声明单元测试或测试先行时，才使用 `$cx-tdd` 和 `$cx-pytorch-tdd`；否则不创建、不修改也不运行单元测试。
4. 为当前一个候选登记假设、比较边界、完整配方、资源预算、日志路径和停止条件。
5. 在外部终端只启动当前候选，并按五分钟节奏读取文件型日志。
6. 训练结束后立即执行同源测试和回测，然后停在诊断状态。
7. 完成六类强制诊断和下一次候选决策，保存原始指标、结论和证据路径。
8. 只有决定为继续且证据支持明确改动时，返回第 4 步构造一个新候选；禁止预先排队。
9. 达到用户目标、用户要求停止、证据表明继续成本不合理或外部条件阻塞时结束循环，并如实说明完成状态。

## 验证证据

- 当前候选的假设、唯一主要改动、固定配置、完整配方、全部样本边界、数据版本和随机种子。
- 启动前资源估算、外部进程信息、标准输出与标准错误路径、逐轮历史和五分钟资源摘要。
- 完成或未完成轮数、停止原因、最后与最佳轮次、训练与验证损失、实际学习率、改善次数、梯度和批量步数事实。
- 数据准备、训练、验证、测试、回测和保存耗时，以及吞吐、图形处理器、显存、系统内存、进程内存和输入输出证据。
- 分类基数、每日正类分布、混淆矩阵、正类召回率、精确率、F1、平衡准确率、精确率—召回率曲线下面积、基线提升和每日前若干名召回、精确率与覆盖率。
- 前若干名收益分布、大跌数量与占比、最差收益、下跌平均损失和尾部平均损失。
- 字段、标签、窗口、归一化、切分、泄漏、恢复、检查点和指标对齐检查。
- 严格测试是否参与选择、比较是否同组以及结论能够覆盖的范围。
- 强制诊断结论和下一次候选决策；如果继续，保存新候选如何由当前证据触发。
- 没有候选在诊断完成前自动启动，且不存在预先固定数量的后台连续执行队列。
