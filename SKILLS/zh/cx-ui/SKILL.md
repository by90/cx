# cx UI 分层

## 目的

用明确的 View、ViewModel、Service、Data 边界组织界面代码，防止页面渲染、界面状态、业务编排、数据库访问、网络请求和测试堆积在同一个文件。框架可以是 GPUI、Web、移动端或其它 UI 框架，职责边界不随框架改变。

## 强制依赖方向

```text
View -> ViewModel -> Service -> Data
```

- View 可以组合页面和组件，并向 ViewModel 发送用户意图。
- ViewModel 可以调用 Service，并把领域结果转换为可展示状态。
- Service 可以调用 Data，并编排一个明确用例。
- Data 只负责数据库、文件、网络或外部系统的读取与写入。
- 禁止反向依赖、跨层直连和循环依赖。View 不得直接访问 Service 或 Data；ViewModel 不得直接访问数据库、网络、文件或 UI 框架元素；Service 和 Data 不得依赖页面、组件或界面状态。

## 文件布局门禁

- 每个可导航页面只放在一个独立页面文件中，一个页面文件只定义一个页面及其紧密私有的布局辅助项。
- 每个可复用或可独立渲染的组件只放在一个独立组件文件中；禁止在页面文件、应用外壳或统一 `ui.rs` 中继续堆积组件实现。
- 每个页面或独立组件的 ViewModel 分别位于独立文件，不得与 View、Service 或 Data 混写。
- Service 按用例职责拆分文件；Data 按数据源或仓储职责拆分文件。一个文件出现两个独立变化原因时必须继续拆分。
- `mod.rs`、索引文件和应用装配入口只声明模块、导出公共入口、组装依赖和选择初始页面，不得包含页面正文、组件渲染、业务规则、查询或持久化实现。
- 测试布局由对应语言测试技能管理；生产 UI 文件中绝对不能混入测试代码。

推荐布局按项目语言调整：

```text
src/
  ui/
    app.rs
    pages/
      quote_page.rs
    components/
      task_progress.rs
  view_model/
    quote_page_view_model.rs
  service/
    quote_update_service.rs
  data/
    quote_repository.rs
```

## 各层职责

### View

- 只负责布局、样式、渲染、导航声明、事件绑定和把用户意图传给 ViewModel。
- 不负责业务判断、数据查询、持久化、协议解析、任务编排、重试策略或跨页面共享状态。
- 页面文件不充当组件仓库；重复或独立渲染单元立即提取为组件文件。

### ViewModel

- 持有页面展示状态、选择状态、加载状态、错误展示状态和由领域结果推导的展示数据。
- 把点击、输入、切换等用户意图转换为明确命令，调用 Service，并处理结果对展示状态的更新。
- 不创建 UI 框架元素，不直接操作控件树，不打开数据库、文件、套接字或网络连接，不实现底层业务算法。

### Service

- 编排一个用例所需的领域对象和 Data 接口，管理业务动作、任务生命周期和跨数据源协作。
- 不持有控件、颜色、布局、页面文案或框架上下文，不返回 UI 元素。
- Service 不是杂项函数仓库；不同用例或不同变化原因使用不同文件。

### Data

- 只负责连接、查询、事务、序列化、协议访问、持久化和资源释放，让底层错误自然暴露。
- 不决定页面状态、按钮可用性、导航、提示文案或展示格式，也不承载本应属于领域或 Service 的业务规则。

## 重构现有巨型 UI 文件

1. 先列出现有页面、组件、展示状态、事件、服务调用、数据访问和测试，记录当前可观察行为与真实调用入口。
2. 先移动测试到语言技能规定的外置镜像目录，再按页面和组件机械拆文件，保持类型、事件和行为不变。
3. 把展示状态和用户意图迁入对应 ViewModel；把用例编排迁入 Service；把数据库、文件、网络和协议操作迁入 Data。
4. 让应用入口只负责依赖装配和导航，删除旧巨型文件中的重复实现与兼容转发，不保留新旧两套路径。
5. 每完成一层拆分都运行项目要求的格式、静态检查、明确声明的测试和真实 UI 验证；只在行为证据一致后进入下一层。

## 审查门禁

以下任一情况都使 UI 交付失败：

1. 一个文件包含多个页面、多个可复用组件，或同时包含 View、ViewModel、Service、Data 中两个以上层级的实现。
2. View 直接查询数据库、读写文件、发起网络请求或实现业务编排。
3. ViewModel 构造 UI 元素或直接访问 Data，Service/Data 引用 UI 框架或展示状态。
4. 页面、组件或 ViewModel 仍集中在统一巨型文件，`mod.rs` 或应用入口继续承载真实页面实现。
5. 为保留旧文件而增加转发层、别名、兼容入口或重复状态来源。
6. 只通过编译或单元测试判断 UI 完成，没有按项目规则启动真实应用并观察受影响交互。

## 与其它 skill 的协作

- 涉及对象职责、领域模型和数据访问边界时同时使用 `$cx-design`。
- 新增可复用组件或公共 UI 能力前使用 `$cx-common-module` 搜索已有入口。
- 用户或当前文档明确要求测试时，使用 `$cx-tdd` 和对应语言测试技能；测试代码仍必须与生产文件隔离。
- 交付前使用 `$cx-review` 检查分层、文件布局、行为证据和真实 UI 观察。

## 输出

记录页面、组件、ViewModel、Service、Data 的文件与一句话职责，明确依赖方向、被删除的巨型入口、行为保持证据、真实 UI 验证结果和剩余风险。
